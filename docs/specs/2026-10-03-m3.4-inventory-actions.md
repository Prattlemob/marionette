# M3.4 — Inventory and container actions

Implemented on Minecraft 1.21.8 / NeoForge 21.8.53. The normative API is in
[protocol/v1.md](../../protocol/v1.md#inventory--menu-addressed-inventory-actions);
[D8a](../decisions.md#d8a--inventory-execution-and-initial-scope--settled-2026-10-03-m34)
records the execution choices.

## Implementation

- Network parsing produces an immutable inventory request with its error context.
  Existing session admission keeps all inventory requests controller-only.
- Client tick execution checks live player state and the actual visible menu.
  Type, container id and server state id must match the supplied menu reference.
- `InventoryRules` provides headless preflight checks for whole-stack moves and
  two-way hotbar swaps. `InventoryActionApplier` isolates Minecraft access,
  resolves player aliases from backing inventories, and issues vanilla clicks.
- Inventory results are reliable per-request snapshots. They do not join the
  coalesced observation stream and do not claim server acknowledgment. M4.2
  still owns the richer periodic inventory section.
- Existing screen-open interaction release, connection ownership and world-exit
  safety paths remain in use. The original implementation had no deferred clicks;
  the animation extension below adds one bounded, cancellable action.

## Verification

`./gradlew build` passes with 201 headless tests. Added coverage includes malformed
inventory requests and slot aliases, id propagation, role refusal, additive
capability/results, and capacity/permission rules for moves and swaps.

A rendered `runClientDemo` joined an isolated copy of the existing test world.
Temporary instrumentation outside the repository provisioned items through
server commands and inspected server state. All inventory actions used the
normal WebSocket protocol, including the committed `examples/inventory.py
--chest` demo. The harness did not implement inventory operations.

| Check | Evidence |
| --- | --- |
| Open/inspect | Survival inventory opened; 46 slots and player aliases returned |
| Whole-stack move | 16 dirt moved from `main.0` to `hotbar.0` |
| Hotbar swap | Server confirmed `main.2` contained one stick and `hotbar.1` contained eight cobblestone |
| Equip | Server confirmed one iron helmet in the head equipment slot |
| Drop one | Dirt stack reduced to 15 before chest deposit |
| Chest through same API | Normal use opened `minecraft:generic_9x3`; generic move deposited 15 dirt into menu slot 0; server confirmed contents |
| Close | Result returned `menu: null`; normal gameplay screen resumed |
| No open menu | Drop refused as `inventory_unavailable` |
| Stale identity/revision | Wrong container id and wrong state id refused as `stale_menu` |
| Impossible actions | Empty source, out-of-range slot, incompatible destination, same-slot move, and crafting slot refused |
| Cursor ownership | Occupied cursor refused close/drop; inspection confirmed slot contents unchanged |
| Observer isolation | Inventory command refused; observer disconnect left controller connected |

No dedicated-server launch or multiplayer server test was performed. Runtime
acceptance covers player inventory and chest; hopper, dispenser/dropper, barrel,
and shulker variants share the adapter but were not individually exercised.
Arbitrary modded menus and custom click semantics are deliberately outside the
initial execution scope. M3.3's human animation review and physical alt-tab check
remain pending and were not marked complete by this work.

Temporary harness sources, worlds and logs live outside the repository. The
final build excludes the harness; no local world or runtime output is committed.

## Animation extension (2026-10-03)

The user requested visible, watchable interaction instead of same-frame changes.
The additive `inventoryAnimation` capability enables `animated: true`; default
wire behavior remains instant, and `examples/inventory.py` animates by default
with an `--instant` escape hatch. See D8b and the current protocol for semantics.

`InventoryCursorMotion` supplies read-only frame interpolation while all clicks,
validation, cancellation and recovery remain on the client tick/input thread.
The screen mixin substitutes only the relevant render pointer and draws an
agent cursor. Vanilla renders the real carried stack. The hover accessor restores
physical pointer hover before human input can use a virtual slot by mistake.

The build now passes 205 tests, including strict animation parsing and cursor
motion bounds, travel limits and dwell. Live checks in the isolated rendered
client established:

- A real carried dirt stack is observable between pickup and placement.
- Additional mutations fail with `inventory_busy`; inspect stays available.
- Release, controller disconnect, and a simulated human key event during carry
  cancel and return all 16 dirt to the original source, leaving the destination empty.
- A replacement screen before pickup cancels without changing slots.
- Foreign cursor contents cancel the action and remain untouched.
- A completed animated move replies after placement; instant mode still works.
- The animated full demo performs move, swap, equip, drop and chest deposit.

A fresh video is recorded outside the repository. Visual inspection checks the
cursor and carried-item rendering. Real OS key events, menu replacement during
carry, multiplayer latency, and every supported container variant were not
separately exercised. M3.3's physical alt-tab acceptance remains pending.
