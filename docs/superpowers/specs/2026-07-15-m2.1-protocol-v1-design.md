# M2.1 — Protocol v1: design

Design for ROADMAP M2.1 (Phase 2). Goal: turn the throwaway v0 draft into a
versioned, documented wire contract in `protocol/` that every later milestone
extends rather than invents, and bring the implementation into exact
conformance.

Decisions resolved during this design (with the project owner):

- **Scope:** M2.1 absorbs only the handshake-adjacent items carried out of
  the Phase 1 review — gating the disconnect latch on a completed hello, and
  duplicate-hello rejection testing. Daemon thread factory, `exceptionCaught`
  diagnosis, and release-vs-bridge-stop shutdown ordering stay with M2.3.
- **Envelope:** flat messages with reserved top-level keys (`type`, `id`) —
  no nested `payload` object. Zero migration friction from v0; less nesting
  for agents; matches the existing parser shape.
- **Rejection path:** fatal protocol violations send a normal JSON `error`
  message as the final frame, *then* close with the matching WebSocket close
  code. Text frames are surfaced reliably by every WS client; close reasons
  are not.
- **Acks:** none. Commands are fire-and-forget; success is silent (the next
  observation shows the effect). Any error caused by a message carrying an
  `id` echoes that id. The id plumbing is specced now so future
  request/response messages (block scan, status query) use it for real
  replies.
- **Architecture:** extract a transport-neutral per-connection session state
  machine (Approach A), over evolving `BridgeServer` in place (leaves
  handshake state implicit — the cause of the spurious-latch bug) and over a
  full message registry/codec layer (machinery ahead of need for six message
  types).

## 1. Wire contract (`protocol/v1.md`)

Written **first**, before any implementation change (protocol-first rule).

### Transport

Unchanged from v0: WebSocket, text frames, one JSON object per frame,
`ws://127.0.0.1:24680/` (port becomes config in M2.2), single controller.
Newly documented (previously implicit in the Netty pipeline):

- Text frames only. A binary frame is a protocol violation → close `1003`.
- Frames exceeding the pipeline aggregation limit → close `1009`.

### Envelope

Every message is a flat JSON object. Reserved top-level keys:

- `type` — required string. Unknown `type` → error `unknown_type`.
- `id` — optional, string or number, echoed verbatim in any reply caused by
  the message. Any other JSON type for `id` → non-fatal `invalid_field`.

Unknown non-reserved fields are ignored (forward compatibility).

### Handshake

First message on a connection MUST be `hello`:

```json
{"type": "hello", "versions": [1], "role": "controller"}
```

- `versions` — required array of integers the agent speaks; the mod selects
  the highest version both sides share.
- `role` — optional, defaults to `"controller"`; the only accepted value in
  v1 (D7). `"observer"` arrives later as a purely additive capability.

Mod reply:

```json
{"type": "hello", "version": 1, "capabilities": {}, "mod": "<mod semver>"}
```

- `capabilities` — empty object in v1. The spec documents the reserved flag
  names (`baritone`, `server`, `vision`, `observer`) and the rule **absent =
  unsupported**, so agents feature-detect with a truthy check (D6).
- `mod` — informational mod version, read from the mod container (not
  hardcoded).

Rejections (fatal — error frame then close):

| Condition | Error code | WS close |
|---|---|---|
| First message is not `hello` | `hello_required` | 1002 |
| No shared version (`supported: [1]` included in error) | `unsupported_version` | 1002 |
| `role` present but not `"controller"` | `unsupported_role` | 1002 |
| Controller already attached (sent immediately after WS upgrade) | `controller_attached` | 1013 |
| Malformed `hello` (missing/invalid `versions`) | `invalid_field` | 1002 |

A repeated `hello` on an active session is **non-fatal**: error
`unexpected_hello`, connection stays open, held controls untouched.

### Commands (agent → mod)

`input`, `look`, `release` — semantics carried over from v0 verbatim
(set-and-hold, omitted-fields-unchanged, both applied only on the client
tick, discarded while no world is loaded), now with the optional `id`.
Success is silent.

### Observation (mod → agent)

Unchanged from v0 (`tick`, `x`, `y`, `z`, `yaw`, `pitch`), re-stated under
the v1 envelope rules. M4.1 replaces the body with the composite frame (D2).
Observations flow **only to a session in `ACTIVE` state** — never during
`AWAITING_HELLO`.

### Errors (mod → agent)

```json
{"type": "error", "code": "invalid_field", "message": "pitch must be a finite number",
 "id": 12, "input": "{\"type\":\"look\",\"id\":12,\"yaw\":0,\"pitch\":\"up\"}"}
```

- `code` — machine-readable string from the documented taxonomy.
- `message` — human-readable explanation.
- `id` — echoed if the offending message carried a valid one.
- `input` — the offending raw text, truncated to 256 characters.

Taxonomy, with fatality documented per code:

| Code | Fatal | Meaning |
|---|---|---|
| `invalid_json` | no | Frame is not parseable JSON |
| `unknown_type` | no | Unrecognized `type` value |
| `invalid_field` | no (fatal only inside handshake) | Field missing, wrong type, or non-finite |
| `unexpected_hello` | no | Repeated `hello` on an active session |
| `hello_required` | yes (1002) | First message was not `hello` |
| `unsupported_version` | yes (1002) | No shared protocol version |
| `unsupported_role` | yes (1002) | Role other than `controller` |
| `controller_attached` | yes (1013) | A controller is already connected |

Non-fatal errors never alter held controls and never close the connection.

### Safety behavior (normative, restating v0 with new precision)

- On disconnect, socket error, or the client leaving the world, all controls
  release within one client tick.
- The release-all latch applies only to sessions that reached `ACTIVE`; a
  connection that never completed `hello` is not a controller and its close
  is not an agent loss.
- Malformed input never crashes the client and never alters held controls.

### `protocol/README.md` — versioning & change process

- Single integer protocol version; bumps **only** on breaking changes (D6).
- Additive features arrive as handshake capability flags; agents
  feature-detect, never version-sniff.
- Unknown-field tolerance is the compatibility mechanism for additive fields.
- Spec-first rule: `protocol/` changes land before implementation changes.
- Decisions affecting the contract are recorded in `docs/decisions.md`.
- `v0-draft.md` is kept with a "superseded by v1" banner.

## 2. Mod-side architecture

New package `com.prattlemob.marionette.bridge.protocol`:

- **`ProtocolSession`** — one per connection; explicit state machine
  `AWAITING_HELLO → ACTIVE → CLOSED`. Consumes raw text frames, returns
  transport-neutral instructions ("send this frame", "enqueue this command",
  "close with code N"). No Netty types — the whole handshake/error surface
  is unit-testable without a socket. State is confined to the single Netty
  event-loop thread, as today.
- **`ErrorCode`** — enum carrying wire string, fatality, and associated WS
  close code, so spec and implementation cannot drift per-code.
- **`MessageParser`** — today's `CommandParser`, evolved: envelope
  validation, per-type field validation, hello parsing with version
  negotiation. Produces commands or hello records; throws typed protocol
  errors carrying an `ErrorCode`.
- Outbound message builders for the hello reply, errors (id echo + truncated
  input), and observations.

**`BridgeServer` shrinks to transport:** Netty pipeline setup, feeding
frames to the session, executing its instructions, owning the
single-controller slot. A second connection while a controller is attached
receives the `controller_attached` error frame immediately after the WS
upgrade, then close 1013.

**Carried items resolved by this shape:** "controller attached" now means *a
session that reached `ACTIVE`* — a probe that connects and never sends
`hello` neither blocks as "already connected" incorrectly nor trips the
release-all latch / spurious agent-disconnect log on close. Duplicate-hello
handling is an explicit `ACTIVE`-state transition with its own test.

**Unchanged:** `MarionetteClient`'s tick-loop drain, `ControlState` and its
applier, `KeyboardInputMixin`. Commands still marshal to the tick thread
exactly as today.

## 3. Testing & verification

- **Unit — `ProtocolSession` state-machine matrix (socketless):** hello-first
  enforcement; version negotiation including rejection with `supported`;
  role default and rejection; duplicate hello non-fatal; unknown type;
  per-field validation; id echo rules (string, number, invalid type);
  input-echo truncation; per-code fatality → close instruction.
- **Unit — `MessageParser`:** evolves `CommandParserTest`.
- **Integration — headless (`BridgeServerTest` style):** v1 handshake
  end-to-end; second controller receives error-then-close-1013;
  connect-never-hello-disconnect does **not** trigger release-all or an
  agent-disconnect log line.
- **Conformance spot-check:** `examples/probe.py` and
  `examples/walk_square.py` updated to the v1 handshake; per the roadmap
  DoD these exercise every message the mod sends/accepts.
- **Live:** `./gradlew runClient` + updated probe walks the player
  (scripted-client verification flow).
