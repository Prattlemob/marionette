# M2.3 — Connection lifecycle, framing, rate & backpressure — Design

**Date:** 2026-07-23
**Milestone:** M2.3 (ROADMAP.md, Phase 2)
**Prerequisites:** M2.1 (protocol v1), M2.2 (config) — both merged.

## Goal

Make the bridge boringly reliable under real load and misbehaving agents:
a slow-reading agent must never grow an unbounded queue, stall the client
thread, or degrade FPS; quitting the game must close the socket cleanly;
ping/pong provides the liveness signal M5.1's watchdog will act on.

## Scope

All five roadmap items **plus** the carry-overs tracked in
`docs/decisions.md` that M2.3 owns:

1. Per-session observation-cadence override via a new `configure` protocol
   message (config divisor from M2.2 stays the default).
2. Latest-wins coalescing for observation frames with a hard bound
   (writability gate — decided during brainstorming).
3. Slow-consumer soak evidence via log counters.
4. Clean listener shutdown on client quit; no orphaned threads.
5. WebSocket ping/pong liveness (no watchdog action yet — that is M5.1).
6. Carry-overs: daemon Netty thread factory; `exceptionCaught`
   diagnostics; release-vs-bridge-stop ordering; explicit
   `ProtocolSession.close()` after a binary-frame violation.
7. Pre-release JSON-strictness fix in `MessageParser`.

Out of scope: watchdog release-on-missed-pong, ping-timeout config
(M5.1); composite observation frame and section mask (M4.1).

## Design

### 1. Protocol additions (spec-first in `protocol/v1.md`)

- New agent→mod message:

  ```json
  {"type": "configure", "rateDivisor": 5}
  ```

  All fields optional; omitted fields unchanged (the `input` set-and-hold
  convention). Success is silent, per the existing command precedent.
  `rateDivisor` must be an integer 1–100 (mirrors the config range);
  anything else is a non-fatal `invalid_field` error. The override lasts
  until disconnect; the next session starts from the config default.
  The message is deliberately generic: M4.1's D2 section mask lands in
  the same message later as an additive field, not a new type.
- Hello reply capabilities gain `"configure": true` (the additive-change
  mechanism `protocol/README.md` prescribes; agents feature-detect).
- Transport-section additions:
  - The mod sends a WebSocket ping every 10 s; agents may also ping and
    the mod pongs automatically.
  - Observation frames may be **coalesced latest-wins** under
    backpressure; the `tick` field exposes gaps, and agents must not
    assume tick continuity. Errors and the hello reply are never
    coalesced or dropped.
  - On game quit the mod closes the connection with WebSocket close code
    `1001` (going away).

### 2. Backpressure: writability gate in `BridgeServer`

Chosen approach (over a pipeline coalescer handler and an event-loop
mailbox): gate `sendObservation` on `Channel.isWritable()`. Observations
are the only writes that flow through `sendObservation`, so error/hello
writes (issued event-loop-side as session actions) are naturally exempt.

- Child channels get an explicit `WriteBufferWaterMark`
  (high 64 KiB / low 32 KiB) — that is the hard bound.
- `sendObservation` (tick thread): channel writable → clear the pending
  stash (latest-wins supersession) and `writeAndFlush`; unwritable →
  store the frame in a one-slot `AtomicReference` and bump an
  `AtomicLong` dropped counter.
- `channelWritabilityChanged` (event loop): channel writable again →
  flush the stashed frame if present.
- Supersession closes the stale-stash race: if a stashed frame misses its
  writability event, the next direct send clears it. `channelInactive`
  resets stash and counter.
- Soak evidence: a dropped-count getter plus a periodic log line from the
  tick loop ("N observations coalesced since last report") whenever drops
  occurred in the interval.

### 3. Ping/pong liveness

- A scheduled task on the event loop sends `PingWebSocketFrame` every
  10 s to the attached controller (constant interval for now; the
  configurable watchdog timeout is M5.1's).
- `WebSocketServerProtocolHandler` is constructed with
  `dropPongFrames=false`; `AgentConnectionHandler` handles
  `PongWebSocketFrame` **before** the text-only check (today any
  non-text frame reaching `channelRead0` closes 1003 — pongs must be
  exempted). A volatile last-pong timestamp is recorded, with a getter
  for M5.1; VERBOSE log per pong.

### 4. Per-session cadence in `MarionetteClient`

- `AgentCommand.Configure(Integer rateDivisor)` parsed and validated in
  `MessageParser` (network thread), applied on the tick thread like every
  other command.
- `MarionetteClient` keeps a session divisor override; effective divisor
  is override-if-set, else config. Cleared on agent loss.
- `MarionetteConfig.observationDueAt` gains a divisor-parameter overload;
  the existing static-config path stays for callers without an override.

### 5. Lifecycle polish (decisions.md carry-overs)

- `NioEventLoopGroup` gets a named **daemon** thread factory
  (e.g. `marionette-bridge`) so a hung event loop can never block JVM
  exit.
- `stop()`: send close `1001` to an attached controller, close the
  listener, `shutdownGracefully` with a bounded await so quit cannot
  hang. Ordering decided and documented: **controls release before
  bridge stop** on shutdown (currently inert because ticks have stopped,
  but the ordering becomes explicit and recorded).
- `exceptionCaught` logs the cause (class + message) at WARN before
  closing instead of closing silently.
- `ProtocolSession` gets an explicit `close()` (→ CLOSED), called on the
  binary-frame violation so already-pipelined text frames are ignored
  instead of parsed and enqueued.

### 6. JSON strictness (pre-release)

`MessageParser` switches to strict parsing (Gson `Strictness.STRICT` via
`JsonReader`). Unquoted keys, single-quoted strings, and trailing garbage
become `invalid_json`. This conforms to the existing spec ("one JSON
object per frame" — JSON per RFC 8259), so it is a bug fix, not a
breaking change; no version bump. Recorded in decisions.md.

## Testing & verification

- **Headless JUnit** (existing test style): coalescing under a stalled
  channel including supersession and counter behavior; `configure`
  parse/validate/apply and reset-on-disconnect; strict-JSON rejections;
  `ProtocolSession.close()`; pong handling and last-pong recording.
- **Live** (scripted client, `Phase1Verify` save): slow-consumer soak —
  a Python agent that completes hello then never reads; log counters
  show drops, FPS unaffected, memory bounded. ≥30 min connected soak
  with no drift, leaks, or disconnects. Game quit observed agent-side as
  a clean 1001 close.
- **`examples/`** updated in the same change (protocol change process):
  the reference agent demonstrates `configure`.
