# M2.2 — Configuration file (design)

**Date:** 2026-07-23
**Milestone:** M2.2 (Phase 2 — Protocol & Bridge Hardening)
**Status:** Approved

## Goal

Make the bridge and its behavior operator-configurable without recompiling:
a NeoForge client config (TOML) covering port, bind address, observation
rate, scan radii caps, the bridge on/off toggle, log verbosity, and the
suppress-pause-on-focus-loss toggle. Schema documented in the README.

## Decisions made during brainstorming

- **Non-loopback bind → clamp, not refuse.** The bridge still starts, on
  `127.0.0.1`, with a loud WARN naming the ignored value. The explicit
  "I understand" opt-out gate for real non-loopback binding is M5.1's job.
- **Observation rate divisor is applied now**, not just defined: a tick-modulo
  check in the send path. M2.3 adds the per-session protocol override and
  backpressure on top.
- **Focus-pause suppression applies only while an agent is connected**
  (hello-completed controller attached), default enabled. With no agent,
  vanilla pause-on-focus-loss behavior is untouched. M5.1 decides
  per-precedence-mode behavior later.
- **Live reload for cheap values.** Values read per-use (divisor, verbosity,
  focus toggle, radii caps) pick up on-disk edits immediately via
  `ModConfigSpec` `.get()` reads. Port, bind address, and the enable toggle
  are read once at startup; changing them requires a restart (documented).
- **Idiomatic `ModConfigSpec` + deferred bridge start** (approach A). No
  hand-rolled config, no STARTUP-type config.
- **No dead feature keys.** `[bridge] enabled` is the feature-toggle
  scaffolding; future optional layers (Baritone, vision) add their own
  toggle in their own section following the same pattern when they ship.
  The observation radii caps are the deliberate exception (the roadmap
  names them as M2.2 deliverables); their comments state when they take
  effect.

## Config schema

One client-type `ModConfigSpec` in a new `MarionetteConfig` class,
generated as `config/marionette-client.toml`:

```toml
[bridge]
    # Master switch: when false, the WebSocket bridge never starts. (restart required)
    enabled = true
    # TCP port for the bridge listener. (restart required)
    #Range: 1 ~ 65535
    port = 24680
    # Bind address. Non-loopback values are ignored and clamped to 127.0.0.1
    # with a warning until the explicit opt-out gate ships (M5.1). (restart required)
    bindAddress = "127.0.0.1"

[observation]
    # Send one observation frame every N client ticks. (live)
    #Range: 1 ~ 100
    rateDivisor = 1
    # Caps for future observation sections (M4.4 entities, M4.5 block scan).
    # Defined now so operators see the ceiling; enforced when those ship. (live)
    #Range: 4 ~ 64
    entityRadius = 32
    #Range: 1 ~ 256
    entityMaxCount = 64
    #Range: 4 ~ 32
    blockScanRadius = 16

[client]
    # While an agent is connected, suppress the vanilla pause-on-focus-loss so
    # the session keeps running and streaming when unfocused. (live)
    suppressPauseOnLostFocus = true

[logging]
    # QUIET: warnings/errors only. NORMAL: lifecycle + connection events.
    # VERBOSE: adds per-tick heartbeat and puppet-position evidence logs. (live)
    verbosity = "NORMAL"
```

Verbosity is an enum (`QUIET < NORMAL < VERBOSE`) enforced at Marionette's
own log sites via a guard in the style of
`MarionetteConfig.verbosity().atLeast(Verbosity.NORMAL)` — no slf4j level
manipulation. Today's heartbeat and puppet-position logs move behind
`VERBOSE`; connection and lifecycle events sit at `NORMAL`; warnings and
errors always emit.

## Lifecycle rewiring

- `MarionetteClient`'s constructor registers the config
  (`container.registerConfig(ModConfig.Type.CLIENT, MarionetteConfig.SPEC)`)
  and no longer starts the bridge (the constructor runs before config files
  load, so it cannot read config).
- Bridge startup moves to `FMLClientSetupEvent` (mod event bus), where
  config values are guaranteed loaded: read `enabled`, `port`,
  `bindAddress` once; resolve the bind address through a pure
  `resolveBindAddress(String)` helper (loopback values pass through,
  anything else returns `127.0.0.1` and the caller logs the WARN); start
  the server.
- `BridgeServer` gains a `bindAddress` constructor parameter replacing the
  hardcoded `"127.0.0.1"` literal in `start()`.
- The shutdown path (`GameShuttingDownEvent`) is unchanged.
- Observation divisor applied in `onClientTickPost`: send only when
  `ticksInWorld % rateDivisor == 0`, reading the divisor live each tick.

## Focus-pause suppression

A small mixin on `Minecraft` targeting the pause-on-lost-focus path (the
`pauseOnLostFocus` check inside `Minecraft#tick`), skipping the auto-pause
when both:

1. the `suppressPauseOnLostFocus` config toggle is on, and
2. `MarionetteClient.instance()` reports a hello-completed controller
   attached (`bridge.hasController()`).

`options.pauseOnLostFocus` itself is never mutated, so the user's
`options.txt` can never be persisted wrong. With no agent attached the
mixin is a pass-through and vanilla behavior is untouched. The exact
injection point is pinned against 1.21.8 mappings during implementation;
if the bytecode shape is hostile to an `@Inject`, the fallback is a
`@Redirect` on the `pauseOnLostFocus` field read within `tick`.

## Error handling & validation

- `ModConfigSpec` ranges auto-correct out-of-range numerics (NeoForge logs
  the correction).
- Non-loopback `bindAddress` → clamp to `127.0.0.1` + WARN naming the
  ignored value and pointing at the future M5.1 opt-out gate.
- Malformed verbosity value → spec default (`NORMAL`).
- `enabled = false` → one INFO line ("bridge disabled by config") so an
  operator can discover why nothing is listening.
- Bridge start failure keeps the existing catch-and-run-without-external-
  control behavior.

## Testing & verification

Headless unit tests (JUnit, matching the existing suite):

- `resolveBindAddress`: `127.0.0.1` / `localhost` / `::1` pass through;
  `0.0.0.0`, LAN IPs, and garbage clamp to `127.0.0.1`.
- Divisor gating arithmetic (send on tick N iff `N % divisor == 0`).
- Verbosity enum ordering / `atLeast` guard.
- `BridgeServerTest` extended to cover the configurable bind address.

Live `runClient` verification against the milestone DoD:

- Change `port` in the TOML, restart → listener moves (log line proves it).
- Set `bindAddress = "0.0.0.0"`, restart → WARN + listener on loopback.
- With an agent connected and the toggle on, alt-tab → no pause menu,
  observations keep flowing; with no agent, alt-tab pauses as vanilla.
- `enabled = false` → no listener, single INFO line.

README gains a Configuration section documenting the schema verbatim
(roadmap item "Config schema defined and documented in README").

## Documentation updates

Beyond the README section, `docs/decisions.md` records the two points this
design resolves: non-loopback bind handling in M2.2 is clamp-with-warning
(opt-out gate deferred to M5.1), and the focus-loss pause suppression
follows the suggested default (only while an agent is connected, enabled
by default; per-precedence-mode behavior still M5.1's).

## Out of scope

- Per-session observation-rate override via protocol message, coalescing,
  backpressure — M2.3.
- Non-loopback opt-out gate, watchdog, panic key, precedence modes — M5.1.
- Baritone / vision feature toggles — added by their own milestones
  (M6.1 / M8.1) following the `[bridge] enabled` pattern.
- Enforcing the entity/block-scan caps — M4.4 / M4.5 read them when they
  ship.
